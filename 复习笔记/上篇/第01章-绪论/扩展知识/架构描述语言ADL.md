# 扩展知识：架构描述语言（ADL）与 C2SADL

> 对应教材 1.1.1「软件架构描述与表示」一段。教材只列名称，本文先讲清 ADL 的共同概念，再详解 C2SADL，最后把其余常见 ADL 逐个做通俗解释。**考试只要求「名称 + 类别/关键词」，不需要学习任何语言的语法。**

教材原文：目前存在多种软件架构描述语言，比较典型的是基于组件和消息的软件架构描述语言 C2SADL，分布、并发类型的架构描述语言 Wright，架构互换语言 ACME，基于组件和连接的架构描述语言 UniCon，基于事件的架构描述语言 Rapide，以及其他比较有影响力的描述语言 Darwin、MetaH、Aesop、Weaves、SADL、xADL 等。

## 1. 什么是 ADL

**架构描述语言（Architecture Description Language，ADL）是用形式化文本描述软件架构的语言**：把系统的构件、连接件、接口以及它们之间的拓扑关系写下来，使架构从「一张只能给人看的图」变成「可分析、可验证、可复用、可演化的形式化说明书」。四种建模模型中的**结构模型**，其研究核心就是 ADL。

几乎所有 ADL 都在描述同一张「架构图」的几个要素：

- **构件（Component）**：干活的模块（计算、存储、界面等）；
- **连接件（Connector）**：构件之间的交互方式（调用、消息、管道、共享数据等）；
- **配置/拓扑（Configuration）**：谁和谁相连、如何组成系统；
- **风格与约束（Style/Constraint）**：系统必须遵守的结构规则（如 C2 的「不直连」）；
- **附加信息**：性能、实时性、部署、可靠性等，供分析使用。

各种 ADL 的差别只在于**更关心哪一类问题**：有的关心消息、有的关心并发、有的关心互换、有的关心实时部署。教材正是用「基于组件和消息」「分布、并发」「互换」「基于事件」来给它们分类的。

## 2. C2SADL 详解

**C2SADL = C2（Component and Message，构件与消息）+ SADL（Software Architecture Description Language）**，即「描述 C2 风格系统的专用架构描述语言」。

C2 风格的四个要点：

| 要素 | 含义 | 通俗理解 |
| --- | --- | --- |
| 构件 Component | 独立功能单元，有**顶部（top）和底部（bottom）两个接口域** | 部门：顶部收通知、发请求；底部收请求、发通知 |
| 连接件 Connector | 负责消息的**路由、过滤、转换**，不承担业务 | 总机收发室 |
| 消息 Message | **请求向上传、通知向下传**，异步发送 | 留言而非当面等待答复 |
| 拓扑规则 | **构件之间不允许直接相连，必须经连接件传递消息** | 部门之间不直接打电话，都走收发室 |

由此带来的好处是**松耦合与可演化**：只要接口兼容，构件可替换、可增删而不影响其他构件，所以 C2 风格适合 GUI 等要求灵活可扩展的应用系统（教材 1.1.3）。

示意性描述（伪代码，非严格语法）：

```
架构 订单系统：
  构件 界面层      // 顶部发请求，底部收通知
  构件 订单处理    // 顶部收请求，底部发通知
  构件 库存查询
  连接件 消息总线  // 负责路由与过滤
  拓扑：
    界面层.bottom   → 消息总线
    消息总线        → 订单处理.top
    订单处理.bottom → 消息总线
    消息总线        → 库存查询.top
```

与相近概念的区别：

- **C2 架构风格**是「怎么设计系统」的风格；**C2SADL** 是「怎么把这种设计写下来」的语言，二者不可混同。
- **事件驱动架构**同样是异步消息，但强调事件队列/分发器/通道/处理器的运行机制；C2 更强调构件—连接件拓扑与顶/底接口域。
- **UML** 是通用建模语言，C2SADL 是面向特定架构风格的专用 ADL，更利于架构级分析与演化验证。

**记忆关键词**：组件、消息、不直连。

## 3. 其他常见 ADL 通俗解释

### Wright：分布、并发类型

CMU 提出的 ADL，用类似 **CSP（通信顺序进程）**的形式化方法描述**分布式、并发系统**：构件是并发进程，连接件是进程之间的**交互协议**。它把每段对话的「剧本」（先说什么、后说什么）写全，可据此推理**死锁、同步、协议不匹配**等并发问题。**关键词：分布、并发、CSP、协议与死锁分析。**

### ACME：架构互换语言

Architecture Interchange Language，CMU 提出。它提供一套**通用的架构表达格式**（构件、连接件、系统、属性、约束等），并允许附加注释保留各 ADL 的个性，充当不同 ADL/工具之间的**中间交换格式**，让架构描述能互相转换、共享。类比：架构界的「翻译官」——各种语言先统一翻成 ACME，再互转。**关键词：互换、共享、中间格式。**

### UniCon：基于组件和连接

CMU 的 Mary Shaw 等提出的 ADL，把**构件和连接件都当作一等公民**：连接件被显式定义成各种类型（管道、远程过程调用、共享数据、事件广播等），再按类型把构件装配成系统。它强调**连接件的规范与复用**，支持异构构件集成，并可由工具辅助生成可运行系统。类比：先选好「接头/插座」的规格，再把设备插上组成整机。**关键词：组件、连接件类型、装配与集成。**

### Rapide：基于事件

斯坦福 David Luckham 等提出的 ADL，用**事件及事件模式（event pattern）**描述系统行为：构件产生事件，其他构件按规则观察、匹配并响应事件，形成因果与时序关系。适合描述分布式、实时系统「某事发生后才触发动作」的行为，便于模拟和分析。类比：监控中心的规则表——「出现 A 且随后出现 B，就执行 C」。**关键词：事件、事件模式、因果与时序。**

### Darwin：分布式系统的配置与动态绑定

英国帝国理工 Magee、Kramer 等提出的 ADL，描述分布式系统的**配置结构**：有哪些组件实例、各自提供/要求什么接口、接口之间如何**绑定（binding）**，并支持**动态配置**（运行中创建/删除组件、改变绑定），可映射到 CORBA 等分布平台。类比：分布式系统的「接线图」，而且允许系统运行中**带电改线**。**关键词：分布、配置、绑定、动态演化。**

### MetaH：实时嵌入式与软硬件部署

Honeywell 提出的 ADL，面向**实时、嵌入式系统**（如航空电子）。既描述软件构件，也描述**硬件平台与部署映射**（哪个构件跑在哪个处理节点上），并可做**实时调度分析**（如速率单调分析 RMA）与可靠性/安全性建模；其后继发展为 **AADL**（SAE 的架构分析与设计语言）。它回答的是嵌入式系统「**来不来得及**」的问题，而不只是「功能对不对」。**关键词：实时、嵌入式、部署、调度分析（后继为 AADL）。**

### Aesop：按架构风格组装系统

CMU 提出的 ADL，强调**架构风格（architecture style）**：先定义一种风格（如管道-过滤器、黑板、C2 等），再在风格约束下组装系统，并检查系统是否违反风格。它把设计经验以「风格」形式显式化、可复用。类比：先选定「建筑风格」（中式/欧式），再按风格盖房并验收是否合规。**关键词：风格、约束、复用与检查。**

### Weaves：把工具编织成集成环境

CMU 提出的 ADL，面向**工具集成（tool integration）**：把编辑器、编译器、调试器、浏览器等各种软件工具视为构件，通过消息/数据流把它们**编织（weave）**成集成的开发环境，描述工具间的互操作与数据交换。类比：把分散的工具串成流水线——上一道工序的输出，自动成为下一道工序的输入。**关键词：工具集成、数据流、编织开发环境。**

### SADL：架构描述语言的通用缩写

SADL 是 **Software Architecture Description Language** 的通用缩写，某些文献也用它特指某一具体语言。教材把它与其他具体 ADL 并列列出，按「一种架构描述语言」理解即可，**不需要单独展开**。**关键词：ADL 的通用缩写。**

### xADL：基于 XML 的可扩展描述语言

eXtensible ADL，用 **XML** 表示架构（构件、连接件、接口、链接、类型、实现映射等），并通过 XML 的结构化与 Schema 机制**按需扩展**（如加入部署、版本、产品族等信息），有 xArch 等工具支持。类比：把架构写成一份「带标签的 XML 数据文件」——人看得懂，程序更好解析，想加新信息就加新标签。**关键词：XML、可扩展、机器可读、工具支持。**

## 4. 总览表与记忆法

| ADL | 类别（教材口径） | 一句话理解 | 记忆关键词 |
| --- | --- | --- | --- |
| C2SADL | 基于组件和消息 | 构件经连接件异步消息通信，不直连 | 组件、消息 |
| Wright | 分布、并发类型 | 把并发交互「剧本」写全，可分析死锁 | 并发、CSP |
| ACME | 架构互换语言 | 不同 ADL 之间的通用中间格式 | 互换、共享 |
| UniCon | 基于组件和连接 | 连接件定型（管道/调用/共享），再装配件 | 组件、连接件 |
| Rapide | 基于事件 | 用事件模式与因果时序描述系统行为 | 事件、模式 |
| Darwin | 分布式配置 | 组件—接口—绑定，支持运行时改结构 | 配置、绑定 |
| MetaH | 实时嵌入式 | 软硬件部署一起建模，核算实时性 | 实时、部署 |
| Aesop | 按风格组装 | 先定风格再组装并检查合规 | 风格、约束 |
| Weaves | 工具集成 | 把各种工具编织成集成开发环境 | 工具、集成 |
| SADL | 通用缩写 | ADL 的通用简称，不单独展开 | 了解即可 |
| xADL | 基于 XML | 架构写成 XML，可扩展、机器可读 | XML、扩展 |

**总记忆法**：先记「五大典型」——**C2 消息、Wright 并发、ACME 互换、UniCon 连接、Rapide 事件**；其余六个了解名称即可（Darwin 配置、MetaH 实时、Aesop 风格、Weaves 工具、SADL 缩写、xADL 的 XML）。
