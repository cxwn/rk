二、知识点笔记

16.1 嵌入式系统概述

16.1.1 发展历程与基本特征

教材原文：嵌入式系统是为了特定应用而专门构建的计算机系统。

通俗地说，它不是「什么都能干的通用电脑」，而是嵌入设备中、围绕明确任务定制的计算系统；软硬件必须协同考虑功耗、成本、体积、环境和响应时限。

阶段核心形态识别特征
单片微型计算机 SCM单片机、无操作系统、汇编功能单一、资源少、几乎无用户接口
微控制器 MCU嵌入式处理器＋简单操作系统外设和接口扩展，开销小、效率高、通用性弱
片上系统 SoC多部件集成到芯片可运行于不同处理器，内核小、兼容性好
Internet 嵌入式系统处理器集成网络接口、设备入网网络化
智能化与云推动端侧微型传感设备＋智能服务设备低能耗、高速度、高集成、高可信

⭐【易错】教材第二阶段标题虽写 MCU，但正文强调「嵌入式微处理器＋简单操作系统」；答题按教材语境描述，不要把五阶段机械等同于五种处理器分类。

16.1.2 硬件体系结构

典型嵌入式系统硬件组成与分级总线（重绘图16-1）
处理器类型一句话理解典型优势与用途
MPU 微处理器处理器核心需外配存储器和外设功能强，但板级器件多、可靠性与保密性受影响
MCU 微控制器内核、存储器和外设单片集成体积小、功耗与成本低、可靠性高，适合控制
DSP 数字信号处理器为乘加等信号算法优化，常采用哈佛结构指令执行与编译效率高，适合音视频、通信
GPU 图形处理器并行承担图形图像运算降低 CPU 图形处理负担
SoC 片上系统把处理器核与多数外设集成到芯片高集成、可剪裁，适合专用终端

⭐【重点】芯片温度等级：民用级 0～70℃，工业级 −40～85℃，军用级 −55～150℃；湿度、振动、加速度也属于选型约束。

存储器核心结论高频辨析
RAM断电丢失，运行时可读写DRAM 需刷新、成本低，常作主存；SRAM 无需刷新、更快，常作 Cache
ROM断电保留，适合固化程序MASK ROM 不可改；PROM 一次写；EPROM 紫外线擦除；EEPROM 电擦除；Flash 可在线改写但先擦后写

总线按信息分为数据、地址、控制三类；按连接位置分为片内、系统、局部、通信总线。通信总线连接主机外部设备或其他计算机，不能与片内总线混淆。

看门狗是系统恢复机制：正常程序周期「喂狗」使计数器复位；程序跑飞后计数器溢出，系统保存关键数据并复位重启。举例：自动售货机控制程序卡死时，看门狗像超时巡检员，强制设备重新启动，而不是一直等待人工处理。

16.1.3 软件架构概述

早期只有「监控程序＋应用软件」，引入 EOS 后形成「应用软件—RTOS—BSP—硬件」层次。BSP 屏蔽目标板差异，支撑可移植性；现代嵌入式架构还吸收事件驱动、构件化、虚拟化和微服务思想，但没有脱离应用场景的万能架构。

GOA 用抽象接口解决开放性与可移植性：直接接口用于上下层功能调用，逻辑接口用于同层基于消息的引用；特点为可移植、可互操作、可剪裁、易获得。

16.2 嵌入式系统软件架构原理与特征

16.2.1 层次化与递归模式

层次化模式与递归模式对比（重绘图16-5、图16-6）
模式核心思想优点与适用
层次化高层抽象由低层具体概念实现关注点分离；适合抽象边界清楚的系统
封闭型层次只能调用同层或下一低层封装、移植性好；跨层开销较大
开放型层次可调用同层或任意更低层性能较好；破坏封装，移植性较差
递归模式重复应用包含关系，持续分解复杂系统可扩展、逐步求精；每步可验证可靠性与实时性

递归设计可自顶向下（从系统到子系统，紧扣用例）或自底向上（从关键类和关系出发，复用领域经验）。

16.2.2 嵌入式操作系统 EOS

教材原文：嵌入式操作系统负责嵌入式系统的全部软、硬件资源分配、任务调度、控制、协调并行活动等工作。

⭐【重点】EOS 特征可归为四组：资源约束（紧凑、可剪裁、可固化、可定制）、环境适应（可移植、硬件适应、标准接口）、运行保障（强实时、强确定、稳定、高质量）、使用方式（弱交互、操作简洁）。嵌入式操作系统通常分为面向控制通信的 RTOS 与面向消费电子的非实时 EOS，不能把「嵌入式」直接等同于「硬实时」。

嵌入式操作系统一般体系结构（重绘图16-7）

与处理器硬件相关的驱动称 ASP，与处理器外围芯片相关的称 BSP；特殊硬件驱动单独设计。内核承担任务、内存、任务间通信、时钟和中断管理，可配置库按需静态或动态剪裁。

宏内核与微内核结构对比（重绘图16-8、图16-9）
对比项宏内核微内核
服务位置用户服务与内核服务同在内核空间多数服务移到用户空间，内核只留基础服务
调用方式功能组件可直接调用客户端与服务经消息通信

教材示例VxWorks 5.5、VRTXL4、WinCE；QNX 亦采用微内核

任务是调度最小单位，可记为「任务＝程序＋执行」。⭐【高频考点】三态转换没有「就绪→阻塞」和「阻塞→执行」：等待事件发生在执行态，事件完成后只回到就绪态，仍需调度器分配 CPU。

任务三种状态及合法转换（重绘图16-10）

实时调度的三个独立分类维度：离线/在线看调度信息何时获得；抢占/非抢占看运行能否被打断；静态/动态看优先级何时确定。它们不能混成同一组互斥选项。

实时调度分类与EDF、LLF、RMS选择依据
算法优先级依据类型与要点
EDF 最早截止时间优先截止时间越早，优先级越高动态、在线；可抢占也可非抢占；每次选就绪队首
LLF 最低松弛度优先松弛度越小，优先级越高动态，主要用于抢占式；须随时间和剩余执行量更新
RMS 单调速率调度周期越短，优先级越高静态优先级，经典周期任务算法；不等于按执行时间排序
助记：EDF 看「死线」，LLF 看「余量」，RMS 看「周期」；死线早、余量小、周期短者优先。

LLF 公式：松弛度 L＝截止时刻 D−剩余执行时间 C′−当前时刻 t。 举例：当前 20ms，任务须在 50ms 完成且还需 10ms，则 L＝50−10−20＝20ms；余量越小越紧急。

固定优先级RMS与抢占式EDF的时序差异（依据图16-11、图16-13重绘）

⭐【易错】RMS 的「最优」限定于静态优先级算法，不表示所有任务集都必然可调度；利用率上界是充分条件而非简单判定「超过就一定不可调度」，案例仍应画时间线验证截止期限。

存储管理目标是地址保护、地址独立、分配回收、提高利用率和扩充主存。

方法核心机制关键优缺点/碎片
分区连续区域分配；静态、可变、可重定位简单，但有碎片与增长受限；可变分区回收时合并相邻空闲区
分页逻辑页与物理页框等大，可离散存放无外部碎片，有页内碎片；页表占内存
分段按代码、数据、栈等逻辑单元划分，长度不等便于共享保护和模块化；有外部碎片
段页先分段、段内再分页兼有模块化与离散分配，管理和硬件开销增加
虚拟存储内存＋外存，以局部性原理按需调入扩大寻址空间，支持映射、共享与保护；需硬件支持

可变分区算法：首次适应取顺序找到的第一个足够空闲区；最佳适应取能满足要求的最小区；最坏适应取最大区，期望剩余区仍可用。⭐【易错】最佳适应并不保证全局碎片最少。

任务间通信机制与消息队列、管道、Socket
机制主要用途必须记住的特点
共享内存高效共享数据结构直接高效，但必须另配互斥/同步保护临界区
二进制信号量同步、互斥基础常用于事件与任务协调
互斥信号量保护共享资源支持互斥、优先级继承、递归等语义
计数信号量管理多个同类资源实例计数随获取、释放变化
消息队列任务或 ISR 与任务间带数据通信缓冲区解耦收发双方；可按 FIFO、优先级等排队
管道单向字节流空时阻塞读、满时阻塞写，通常 FIFO
Socket/远程调用跨机网络通信抽象 TCP/IP 操作，采用打开—读写—关闭模式
Signals异步事件通知、异常处理软件层模拟中断，接收者无需主动等待

典型产品抓定位：VxWorks 强调高性能、可靠与广泛应用；LynxOS 强调分布式硬实时；Nucleus 内核小、组件化、易移植；QNX 为微内核 RTOS；Android/iOS 面向移动终端；ROS 提供机器人硬件抽象、消息与功能包生态。产品版本与市场份额属于时效信息，案例不宜当作固定结论背诵。

16.2.3 嵌入式数据库 ERTDBS

嵌入式数据库嵌入应用程序进程，轻量、低内存、可零配置，并强调定时限制、可预知性和底层控制。嵌入性不必然推出实时性，移动性也不必然推出嵌入性。

嵌入式数据库的内存、文件与网络三类架构
类型数据主位置优势主要代价/适用
内存型 MMDB主拷贝常驻内存避免磁盘 I/O，事务时间易预测，实时性好内存与持久化设计要求高；如 eXtremeDB
文件型 FDB本地文件简单、轻便、随应用部署文件格式可被直接读取时安全性弱；如 SQLite
网络型 NDB远程服务器客户端小、支持丰富 SQL、便于集中管理依赖通信与同步；由客户端、协议、远程服务器组成

⭐【重点】数据库服务器通过驱动和 TCP/IP 访问独立进程，数据与程序分离；嵌入式数据库把库链接进应用，经 API 同进程访问，访问控制更多交给应用，部署也随应用一起发布。

SQLite模块化架构（重绘图16-18）

SQLite 四子系统：接口（C API）→编译器（分词、语法分析、代码生成）→虚拟机 VDBE（执行字节码）→后端（B-tree、pager、OS 接口）。举例：手机离线记账应用把 SQLite 库直接打包进 App，不启动独立数据库服务器，也能用 SQL 管理本地账务。

核心功能包括高效存储、锁与数据安全、实时事务、恢复；设计时重点关注内存空间、完整性、并发封锁粒度、变化数据转储和日志缓冲。实时数据库锁开销相对更高，教材建议常以一张关系表为封锁单位，不能照搬通用库「越细越好」的直觉。

产品比较：SQLite 小巧、支持 ACID；Berkeley DB 多语言 API、可伸缩；Firebird 嵌入版支持 SQL、事务、存储过程和触发器；eXtremeDB 是面向实时的内存数据库。

16.2.4 嵌入式中间件

中间件位于操作系统、网络和数据库之上、应用之下，既实现互连，也实现互操作。嵌入式中间件屏蔽底层异构性，共性是通用、异构、分布、协议规范、接口标准，并需适应无线网络、流媒体、QoS 和环境变化。

消息中间件两种模型与CORBA、DDS定位
模型/技术核心机制高频结论
点对点 PTP消息写入指定队列，由一个消费者处理可持久化，接收者暂不可用时队列保存消息
发布—订阅 Pub/Sub发布者按主题发消息，多个订阅者接收双方不必互相了解；持久订阅可补收离线消息
分布式对象/CORBAORB 作为软总线，IDL 定义对象接口跨语言、跨平台调用；公共服务含命名、事务、安全等
DDS以数据为中心的发布/订阅，丰富 QoS去中心化数据分发、强实时、跨平台、支持多种物理协议

消息中间件两个特点是异步处理与松耦合。举例：支付系统只把「已支付」事件写入队列，订单系统稍后消费；两端不必同时在线，也不必知道彼此内部实现。

嵌入式中间件主要功能为网络通信、存储管理和数据处理。CORBA 偏对象请求代理与分布式对象互操作，DDS 偏实时数据分发与 QoS，案例选型不要互换。

16.3 嵌入式系统软件架构设计方法

方法驱动与核心动作适用判断
ABSD业务、质量、功能需求共同驱动；自顶向下、递归细化，使用架构模板总体功能框架明确后迭代设计，需求抽取与设计并行
ADD以质量属性场景为输入，递归选择模式与战术、分配功能安全攸关或质量约束突出的系统
DARTS把实时系统分解为并发任务并定义任务接口工业控制、航空航天、轨道交通等并发实时系统

ADD 的质量场景六要素为刺激源、刺激、环境、制品、响应、响应度量；同一需求可能同时影响性能、安全性和可用性，不同利益相关者也应进入场景分析。举例：外部传感器（刺激源）在正常负载下提交采样数据（刺激、环境），采集服务（制品）须在 20ms 内完成处理并记录超时次数（响应、响应度量），六要素就能完整落地。

ADD七步迭代与DARTS五步开发过程（重绘图16-24）
助记：ADD「审—驱—元—念—例—图—评」：评审输入、选驱动因子、选系统元素、选设计概念、实例化并定接口、草拟视图记录决策、分析评审是否再迭代。

DARTS 五步：RTSA 建立系统规范（SCD、DFD/CFD、STD）→划分并发任务→定义消息/事件/IHM 接口并分配时间预算→把每个任务作为顺序程序细化模块→形成 RTSA 规范、任务结构规范和任务分解。其优势是显式处理并发和接口；不足是任务仍按结构化方法拆成模块，且 RTSA 做不好会直接影响任务划分。

16.4 嵌入式系统软件架构案例分析

HarmonyOS四层架构与分布式核心能力（重绘图16-27）

HarmonyOS：内核层（多内核、KAL、HDF）→系统服务层（四类子系统集，可按子系统/功能裁剪）→框架层（多语言框架、Ability 与 API）→应用层（系统/第三方应用）。⭐【重点】FA 有 UI，PA 无 UI、负责后台任务和数据访问抽象。

分布式四项能力：软总线负责发现、连接与传输；设备虚拟化融合资源形成超级虚拟终端；数据管理使数据跨设备衔接；任务调度依据设备能力、位置和负载选择执行设备。安全可概括为「正确的人—正确的设备—正确地使用数据」，结合协同认证、可信运行环境与数据分类分级。

GENESYS腰型服务架构与四类构件接口（重绘图16-29、图16-30）

GENESYS 面向安全攸关、跨领域嵌入式系统，以「窄腰核心＋可选服务」控制复杂性：核心服务强制、最小、简单、确定，如全局时间和消息传输；选择服务开放扩展；领域专用服务如汽车 CAN；应用专用服务含中间件。

其关键思想是计算与通信分离，构件仅暴露接口，基本交往采用多播单向消息。四类接口：LIF 构件间综合服务、LI 本地 I/O 环境、TII 配置与资源管理、TDI 内部诊断。三级集成为芯片级、设备级、系统级；健壮性靠故障隔离、重启与复制，能效可通过构件迁移到 ASIC、功率门控和时间触发通信改善。

FreeRTOS可裁剪软件架构（重绘图16-31）

FreeRTOS/物联网操作系统：硬件→BSP 驱动→可剪裁内核→网络/安全/POSIX 组件→MQTT、HTTPS、OTA 等定制服务→应用。物联网操作系统还关注芯片、终端、边缘、云多层面，核心质量要求是内核与架构可伸缩、实时、高可靠、低功耗；低功耗可结合休眠、节能和降频设计。

三、重点与易错点

#考点必须记住的结论易错提醒
1处理器选型MCU 单片集成，DSP 面向信号算法，SoC 高集成MPU 不等于 MCU；DSP 不是通用 GPU
2温度等级0～70、−40～85、−55～150℃工业级下限是 −40℃，军用级上限是 150℃
3存储器DRAM 刷新，SRAM 无需刷新；Flash 先擦后写且断电保留EEPROM 是电擦除，EPROM 是紫外线擦除
4看门狗正常喂狗，异常溢出并复位看门狗不是任务调度器，也不能替代故障安全设计
5层次模式封闭型移植性好，开放型性能较好「开放」不是无条件更优
6宏/微内核宏内核直接调用性能高；微内核消息通信、隔离扩展好微内核并非所有服务都在内核态
7任务三态阻塞事件完成后进入就绪，不直接执行不存在就绪直接到阻塞
8调度分类离在线、抢占性、静动态是三个维度RMS 是静态；EDF 是动态；二者不冲突于抢占维度
9三种算法EDF 截止早，LLF 松弛小，RMS 周期短LLF 用剩余执行时间，不用原始总执行时间
10RMS 最优性只在静态优先级算法范围内成立利用率超上界只是不能由充分条件保证，不是必然失败
11分页/分段分页有页内碎片，分段有外部碎片段页式不是「先分页再分段」
12通信机制管道空堵读、满堵写；Signals 异步；消息队列解耦共享内存本身不自动保证互斥
13嵌入式数据库与应用同进程，经 API 访问；内存型利于时间预测嵌入性不必然等于实时性
14中间件PTP 对队列，Pub/Sub 对主题；DDS 以数据为中心且有 QoSCORBA 的 ORB 与 DDS 的发布订阅不要混述
15交叉开发宿主机编译，目标机运行；驻留 Agent 在目标机编译器运行位置与生成代码运行位置不同
16三种设计方法ABSD 需求组合驱动，ADD 质量场景驱动，DARTS 并发任务驱动ADD 不是按功能列表分解；DARTS 不是调度算法
17HarmonyOS四层；FA 有 UI、PA 无 UI；分布式四能力KAL 屏蔽多内核差异，HDF 管驱动
18GENESYS核心服务最小且强制；计算通信分离；LIF/LI/TII/TDI 分工TII 管配置资源，TDI 才看内部诊断
